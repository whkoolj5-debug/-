## 1. 처음 실행하기 (Windows)

1. Node.js 24 LTS를 설치합니다: https://nodejs.org/
2. ZIP 압축을 풀고 해당 폴더에서 터미널을 엽니다.
3. `npm ci`를 실행합니다.
4. `.env.example`을 복사해 `.env`로 이름을 바꿉니다.
5. 아래 세 항목을 넣습니다. 토큰은 채팅에 보내지 마세요.
   - `DISCORD_TOKEN`: Discord Developer Portal → Applications → 앱 → Bot의 토큰
   - `CLIENT_ID`: 앱의 Application ID
   - `GUILD_ID`: 디스코드 개발자 모드를 켜고 서버 우클릭 → 서버 ID 복사
6. Developer Portal의 설치 설정에서 `bot`, `applications.commands` 범위를 사용해 봇을 서버에 초대합니다.
   권한은 채널 보기, 메시지 보내기, 메시지 기록 보기, 파일 첨부, 링크 임베드입니다. 관리자 권한은 필요 없습니다.
7. `npm run check`로 로컬 설정 형식을 검사합니다. 토큰 값은 출력하지 않습니다.
8. `npm run check:discord`로 토큰과 Application ID 일치, 서버 접근, 등록 명령어 수, Gateway 연결과 채널 권한을 검사합니다.
   이 검사는 메시지를 보내거나 명령어/잔액을 변경하지 않고 종료합니다. 등록 전 명령어 0개는 정상입니다.
9. `npm run register`를 실행하면 이 서버의 앱 슬래시 명령어 목록을 등록/갱신합니다.
10. `npm start`로 실행합니다. `Ready:` 로그가 나오면 연결되었습니다. 기본값은 **테스트 모드**입니다.

macOS/Linux에서는 `cp .env.example .env`, Windows PowerShell에서는 `Copy-Item .env.example .env`로 설정 파일을 만듭니다.
기존 `.env`가 있으면 복사로 덮어쓰지 말고 직접 편집하세요. Bot Token만 `DISCORD_TOKEN`에 입력하며, Client Secret/Public Key는 사용하지 않습니다.
일반 채팅 명령어 !bal·!pay·!add-money을 쓰려면 Developer Portal → Bot → Privileged Gateway Intents → Message Content Intent를 켜고 봇을 재시작하세요. Server Members/Presence intent는 필요 없습니다. 설정 전에는 봇을 @멘션한 뒤 !bal을 입력할 수 있습니다. 봇은 활성화된 Message Content 권한만 요청하므로 설정이 꺼져 있어도 포커 연결을 유지합니다.
토큰은 로컬 `.env`에만 보관하고 ZIP, Git, 채팅, 스크린샷에 포함하지 마세요. 노출했다면 Developer Portal에서 재발급하세요.

### 실제 서버에서 확인하는 순서

- 테스트 모드로 실행하고 `!bal`의 테스트 잔액 표시와 `/포커 카드목록`의 개인 응답을 확인합니다.
- `/포커 테이블 만들기`로 생성하고 `/빅 스몰 설정`으로 블라인드를 확정합니다.
- 2명 참여 후 방장의 `/포커 관리`에서 START를 눌러 카드, 콜/체크/레이즈, 다음 판을 확인합니다.
- 시작 전 취소 시 참가비 반환도 확인합니다. 실제 언빌리버봇 연결은 이 확인을 마친 뒤 별도 DB로 전환합니다.
- 명령어가 안 보이면 초대 서버와 `GUILD_ID`, `applications.commands` 범위, 명령어 등록 성공 여부를 확인합니다.
- 401은 토큰, 403/서버 접근 실패는 초대 및 권한, Gateway 시간 초과는 방화벽과 WebSocket 연결을 확인합니다.
  채널별 권한 덮어쓰기도 확인하세요. 연결 검사는 채널 권한을 정적으로 검사하며 실제 메시지/이미지 전송은 위 순서로 확인해야 합니다.

`npm run check`와 실행/등록은 `CLIENT_ID`, `GUILD_ID`, 토큰을 필수로 검사합니다.
`TURN_SECONDS`는 1~86400, `PORT`는 1~65535 정수여야 하며 잘못된 설정이면 DB를 열기 전에 중단합니다.

## 2. 테스트 모드와 실제 언빌리버봇 연결

`ECONOMY_MODE=test`는 사용자마다 5,000,000의 독립 테스트 잔액을 만듭니다.
언빌리버봇 잔액은 읽거나 차감하지 않습니다. 공개 테이블에도 테스트 표시가 나옵니다.

실제 서버 가상화폐를 연결하려면 https://unbelievaboat.com/applications 에서 API 토큰을 발급하고
대상 서버에 잔액 읽기/수정 권한을 허용합니다. `.env`에 다음을 설정한 뒤 재시작합니다.

```
ECONOMY_MODE=live
UNBELIEVABOAT_API_KEY=발급받은_API_토큰
```

잔액은 cash + bank 합산입니다. 참가 시 cash부터 사용하고 부족분은 bank에서 차감합니다.
정산금은 cash로 지급합니다. 참가 시 이미 차감했으므로 전액 잃어도 다시 차감하지 않습니다.
다른 봇/명령어의 동시 지출까지 API가 원자적으로 잠그는 기능은 제공하지 않으므로,
라이브 시작 전 작은 금액으로 서버에서 잔액 변화를 확인하세요.
**테스트와 라이브는 별도의 DB/볼륨을 사용하세요.** 기존 테스트 게임 DB로 라이브를 실행하면 봇이 중단됩니다.

| `!reset-money @유저` | 관리자 합계 잔액 전부 차감 |

| `/ㅈㅈ` | 개인 YES/NO 확인 후 남은 칩 전액 기부 + 폴드 |

디스코드의 일반 채널 입력은 다른 사람에게 보이므로 금액은 개인 입력창으로 받습니다.
빅 입력 후 개인 메시지의 ‘금액 입력’을 눌러 스몰을 입력합니다. NO는 빅 입력창부터 다시 엽니다.
`10,00`은 잘못된 금액으로 거부하고 `10,000`은 10,000으로 읽습니다.
방장은 기본 1번 자리에 앉습니다. 다른 참가자는 공개 참여 버튼 → 회색 1~7 버튼으로 선택합니다.
좌석 버튼은 디스코드 제한에 맞춰 5개 + 2개로 나뉩니다. 좌석 확정 직전에 잔액을 다시 검사합니다.

방장의 개인 관리 화면이 열려 있으면 2명째 참가 시 START가 자동으로 생깁니다.
디스코드 개인 응답의 갱신 가능 시간(약 15분)이 지나거나 봇을 재시작한 경우 `/포커 관리`로 다시 엽니다.
공개 화면에는 START가 나타나지 않습니다. 모든 시작/설정 동작은 방장 권한도 다시 확인합니다.

플레이어는 ‘내 카드 보기’를 눌러 본인 패를 확인합니다. 공용 카드는 플롭 3장 → 턴 1장 → 리버 1장으로
테이블 가운데 공개됩니다. 체크/콜/레이즈/올인/폴드 버튼은 본인 차례에만 작동합니다.
레이즈 입력은 **이번 베팅 라운드의 내 총 베팅액**입니다. 예: 현재 20,000에서 40,000으로 레이즈하려면 40,000 입력.
빠른 베팅의 숫자도 **이번 라운드의 총 베팅액**입니다. ½ 팟/팟은 먼저 콜한다고 가정한 팟을 기준으로 레이즈합니다.
예: 현재 팟 30, 콜할 금액 20이면 팟 버튼의 레이즈 총액은 현재 베팅 20 + (30 + 20) = 70입니다.
최소 레이즈보다 작거나 내 칩보다 큰 선택은 나오지 않습니다. 짧은 올인 후 권한이 닫혀 있으면 레이즈 버튼도 제한됩니다.
금액이 같은 빠른 버튼은 하나만 표시합니다. 버튼을 누른 직후 서버가 차례와 최신 revision을 다시 확인합니다.
90초 동안 행동하지 않으면 체크 가능 시 체크, 아니면 폴드합니다. 자동 전액 포기는 하지 않습니다.

판이 쇼다운까지 가면 **폴드하지 않은 사람의 패와 족보**가 공개됩니다.
상대가 모두 폴드해 끝난 판은 승자의 패도 공개하지 않습니다. 폴드한 패는 기록 파일에도 포함되지 않습니다.
수령액은 팟에서 받은 총액이고 순증감은 수령액에서 이번 판에 넣은 칩을 뺀 값입니다.

`/포커 기록` → ‘판 다시보기’로 각 행동을 되짚을 수 있습니다. 다시보기는 개인 응답이며 실제 게임에 영향을 주지 않습니다.
최근 10판, 각 판 최근 200개 행동을 보관합니다. 업그레이드 전에 저장되지 않은 단계는 복원할 수 없습니다.
기록 JSON은 공용 카드·공개 쇼다운·행동·칩 변화만 포함합니다. 실제 DB에는 진행 복구용 비공개 패도 있으므로 DB를 공유하면 안 됩니다.

한 판이 끝나면 방장 관리 화면의 ‘다음 판 시작’으로 이어갑니다. 딜러/블라인드 위치는 순환합니다.
게임을 시작할 때만 최소 2명이 필요합니다. 전체 칩을 잃은 사람과 포기자는 다음 판에서 제외합니다.
마지막 한 명이 남으면 자동으로 잔액을 정산하고 테이블을 닫습니다. 진행 중 임의 현금화/취소는 없습니다.
시작 전에는 방장이 테이블을 취소해 모든 참가비를 돌려줄 수 있습니다.

## 4. 포기와 사이드팟

회색 ㅈㅈ 버튼과 `/ㅈㅈ`는 동일합니다. YES 시 남은 칩을 모두 현재 팟에 넣고 영구 포기합니다.
이미 이번 판에서 일반 폴드했더라도 포기할 수 있습니다. 포기자는 패가 좋아도 팟 수령 대상에서 제외됩니다.
포기 기부금 때문에 상대가 추가 콜을 강요받지는 않습니다.
일반 올인은 사이드팟을 나눠 각 참가자의 기여 한도에 따라 지급합니다.
포기 기부금 중 승리 가능한 참가자가 없는 상위 팟은 가장 낮은 유효 팟의 승자들에게 배분합니다.
동점이면 균등 분할하고 남는 1칩은 딜러 왼쪽부터 승자 순서로 배분합니다.

## 5. 재시작과 거래 확인

게임 상태, 덱, 패, 차례, 거래 기록은 SQLite에 저장됩니다. 같은 DB로 재시작하면 이어집니다.
정상 완료한 거래번호는 다시 실행해도 중복 지급하지 않습니다.
언빌리버봇 요청 후 네트워크가 끊기면 실제 반영 여부를 알 수 없으므로 자동 재시도하지 않습니다.
해당 참가 처리를 일시정지하거나 정산 완료를 기다립니다.

서버 관리자는 `/포커거래 목록`에서 미확정 거래를 확인한 후 **언빌리버봇 거래/감사 기록으로 실제 반영 여부를 확인하고**
`/포커거래 확인 거래번호:... 반영됨:True/False`로 기록합니다.
미반영 참가비는 다시 참여 버튼을 누릅니다. 생성자 참가비가 미반영이면 `/포커 관리`에서 대기 테이블을 취소하고 다시 만드세요.
정산 중이면 방장이 `/포커 관리`의 ‘정산 이어서 처리’를 사용합니다.
확인하지 않고 True/False를 임의 선택하면 잔액 불일치가 생깁니다.
DB는 개인 패도 포함하므로 공개로 올리지 말고 정기 백업하세요. 한 DB에는 봇 프로세스 하나만 실행합니다.

## 6. 24시간 클라우드 실행

Docker가 설치된 상시 실행 VPS에서 폴더를 올리고 `.env`를 설정한 뒤 실행합니다.

```
docker compose build
docker compose run --rm poker npm run register
docker compose up -d
docker compose logs -f
```

`restart: unless-stopped`로 서버 재부팅 후에도 다시 실행합니다. `poker-data` 볼륨에 게임/잔액 DB를 보관합니다.
볼륨을 삭제하면 복구할 수 없습니다. 무료 절전 호스팅은 상시 실행용으로 적합하지 않습니다.
헬스 체크는 3000번 포트에서 응답합니다. Discord/언빌리버봇으로 나가는 HTTPS 연결이 필요합니다.

## 7. 카드 및 검증

`assets/cards`에는 52장 각각의 PNG/SVG와 숫자·무늬 매핑 manifest가 있습니다.
A는 중앙 무늬 1개, 2~10은 해당 숫자만큼 무늬를 코드로 배치합니다. J/Q/K는 각기 다른 모자/왕관의 대칭 인물 도안입니다.
이미지 생성 모델의 잘못된 숫자를 사용하지 않습니다. `npm run cards`로 같은 디자인을 다시 생성할 수 있습니다.
테이블은 SVG로 자체 제작한 1200×780 펠트 테이블이며 1~7 좌석에 닉네임·칩·베팅·딜러 표시를 합성합니다. 기존 table.png 원본은 자료로 보관합니다.
한글 글꼴은 Noto Sans KR (SIL Open Font License, assets/fonts/OFL.txt)을 포함합니다.

`npm test`: 기존 게임·거래 테스트와 빠른 베팅, 권한/이전 판 버튼 차단, 실제 Discord 핸들러(통신 모의), 판 기록/다시보기 복구, 이미지 비공개 패 누출 방지를 검사합니다.
`npm run preview`: 토큰 없이 7인 데모를 진행하고 `work/preview/`에 테이블·테마·기록 미리보기를 생성합니다.
미리보기는 데모 데이터이며 실제 Discord에 메시지를 보내지 않습니다.
실제 Discord 서버와 실제 언빌리버봇 API의 종단 간 확인은 사용자 토큰/서버 설정 후 필요합니다.
